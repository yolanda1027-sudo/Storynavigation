# 故事導航 Story Navigator

SillyTavern 第三方 UI 擴充。在主聊天之外維護「劇情導航＋幕後推手」，讓重要 NPC／勢力在玩家沒參與時也持續追求自己的目標，並把適合揭露的後果以背景事實交給主模型。

插件**不**替玩家決策、**不**模擬瑣碎日常、**不**改寫角色卡與世界書、**不**強行拉回原著。

> 目前進度：**Phase 3｜自動化與重算**（自動推進、路線重算、樓層變動提示、世界時間），加上提議新支線／推手、推手按兵不動與衝突裁決

## 安裝

1. 酒館右上角「擴充功能」（積木圖示）→ **Install Extension**
2. 貼上 `https://github.com/yolanda1027-sudo/Storynavigation`
   - 若要安裝開發分支，在分支欄位填 `claude/new-session-sqahhz`
3. 安裝完重新整理頁面

更新：擴充功能 → Manage Extensions → 故事導航旁的更新按鈕，然後重新整理。

## 在哪裡打開

- **擴充設定區**：擴充功能面板右欄的「故事導航」抽屜
- **浮動視窗**：聊天輸入框左邊的魔杖選單 →「故事導航」，或面板上的「浮動視窗」按鈕（手機上會佔滿螢幕寬度）

## 基本流程

1. **設定 AI 連線**：「設定與資料 → AI 連線」選擇連線方式
   - 跟隨目前酒館 API：用酒館正在用的 API／模型，但只送插件組好的內容
   - Connection Profile：用酒館 Connection Manager 存好的設定（沒有啟用 Connection Manager 時不會出現）
   - 自訂 OpenAI 相容 API：填 Base URL、API Key、模型（可按「抓取模型列表」）；請求透過酒館後端轉發
2. **建立導航**：按「用 AI 建立導航」→ 會自動跳到「推進控制」的待確認結果 → 確認後按「套用」（會參考角色卡、世界書、近期聊天與 User 人設）
3. **推進劇情**：聊一段之後，到「推進控制」按「推進劇情」
   - 先從上次推進之後的新訊息偵測劇情節點
   - 再讓每個啟用中的推手推進一次（判斷計畫是否還可行、產生行動與結果）
   - 結果進「待確認」：套用／編輯後套用／捨棄／重新生成
4. **注入**：套用後，事件的「可察覺後果」會以背景事實注入主聊天，經過 N 則 AI 回覆後淡出；真相不會注入

開啟插件、切換聊天都**不會**自動呼叫 AI。

## 模式

在「推進控制 → 此聊天 → 模式」切換：

- **手動**：只在按「推進劇情」時推進
- **自動**：每累積 N 則 AI 回覆自動推進一次（N 在「全域推進設定」調整，預設 5）
  - 有待確認的結果還沒處理時，不會自動推進（除非開啟「自動套用」）
  - 自動推進失敗不會一直重試，要再累積 N 則 AI 回覆才會再試
- **暫停**：不自動推進，也暫停注入主聊天；手動推進仍可用

## 路線重算

推進時，節點偵測會對照每條路線的成立／失效條件。失效條件成立、成立條件達成，或核心人物／資源消失時，
只重算受影響的路線，推手接著依新的路線推進。也可以在路線卡片勾「需要重算」，下次推進時重新評估。
重算不會抹除玩家已確定的結果，也不會強行拉回原著。

## 推手怎麼行動

- 推手**不一定每次都行動**：在等時機、觀望或時間太短時，會「按兵不動」，只更新心裡的打算
- 推手**依序行動**：後面的推手如果合理察覺到前面推手這一輪做的事，就能據此反應；沒察覺到的看不到
- **衝突裁決**（預設開，會多一次 AI 呼叫）：大家都行動完後，檢查有沒有互相干擾（搶同一樣東西、撞見彼此…），必要時調整結果

## 提議新支線／推手

- **手動要求**：「推進控制」按「讓 AI 提議新支線／推手」
- **自動提議**（預設關）：在「全域推進設定」開啟後，推進時若距離上次提議已累積 N 則 AI 回覆（預設 15），就順便提議
- 提議會放進待確認結果，每一項都要勾選才會加入；受支線／推手上限限制，也不會和現有的重複

## 同場的推手

節點偵測會判斷哪些推手在聊天最後仍和玩家同場。同場的推手只更新心中的盤算，不產生行動或注入，
場景裡會發生什麼交給主聊天。推手也不會對玩家角色動手，或寫目前時間之後的事。

## 樓層變動提示

AI 偵測出的節點會記下來源訊息。訊息被刪除、修改或換了 swipe 時，上方會出現提示（**不會自動回溯**），可以選：

- **回到記錄前**：跳回還沒有這些節點時的快照（之後推出的內容也會退回，可以用「重做」回來）
- **只刪除節點**：保留其他內容，下次推進會重新讀那幾樓
- **忽略**：以目前的訊息為準

## 資訊隔離

推手推進時，每個推手只會收到：自己的資料與 knowledge、自己相關的路線、「知道的推手」包含他的節點、他自己做的或被告知的事件，以及其他推手的名字。
其他推手的資料、聊天原文、他不知道的真相都不會送出。
預設每個推手分開呼叫；可以在設定關掉改成合併一次呼叫（較省，但隔離較弱）。
送出的完整內容可以在「設定與資料 → Debug → AI 呼叫紀錄」檢查。

## 失敗時

API 失敗、逾時、JSON 壞掉或格式不符時，結果不會寫入，既有導航與事件不受影響；錯誤訊息旁有「重試」。
不會自動重試。原始輸出保留在 AI 呼叫紀錄裡。

## 各分頁

| 分頁 | 內容 |
| --- | --- |
| 劇情導航 | 主線／支線（所有欄位可編輯）、劇情節點（含「知道的推手」）、變化紀錄（可回到任一步） |
| 幕後推手 | 推手資料、knowledge、相關路線、最新行動 |
| 世界事件 | 「真相／可察覺後果」兩欄、玩家是否已知、誰知道 |
| 推進控制 | 模式（手動／自動／暫停）、世界時間、推進劇情／建立導航、自動推進狀態、樓層變動提示、待確認結果、推進頻率（預設 5）、支線／推手上限（預設 3／3） |
| 設定與資料 | AI 連線、輸入預算（預設 8000）／輸出上限（預設 3000）、讀取則數、Lorebook 選擇、注入設定、Prompt 模板、匯出／匯入、Debug（資料來源檢視、AI 呼叫紀錄） |

- 資料存在每個聊天的 `chatMetadata.storyNavigator`，不同聊天互不影響。
- 每次正式寫入都存一份快照，可復原／重做，預設保留 30 份。
- 自訂 API 的金鑰會跟其他擴充設定一起存在酒館設定檔，酒館的金鑰保管機制不會保護它；介意的話請用 Connection Profile。

## 檔案結構

```
manifest.json
index.js              入口：註冊事件、掛 UI
src/state.js          狀態讀寫、快照、undo/redo、驗證
src/llm.js            所有 AI 呼叫的統一出口（三種連線、逾時、任務鎖、JSON 容錯解析）
src/reader.js         M1 讀取角色卡、世界書、聊天，依預算裁切
src/prompts.js        所有 prompt 模板（可在設定覆寫）
src/navigator.js      M2 建立導航
src/detector.js       M4 節點偵測
src/actors.js         M3 推手推進（含計畫可行性判斷、同場判斷）
src/recalc.js         M5 路線重算
src/arbiter.js        推手衝突裁決
src/propose.js        提議新支線／推手
src/auto.js           自動推進
src/backtrack.js      樓層變動提示與回溯
src/injector.js       M6 注入
src/pending.js        待確認結果的套用／編輯／捨棄
src/ui/panel.js       介面主體（五分頁、浮動視窗）
src/ui/ai.js          AI 相關介面
src/ui/common.js      介面共用工具
templates/panel.html
style.css
```
